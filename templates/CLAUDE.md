# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this request workspace.

## What this is

This is an **HPC troubleshooting request workspace** on the Boston University SCC, created by `new_request.sh`. An HPC facilitator uses it to reproduce and debug a researcher's R issue in isolation from their home directory. Your job is to help diagnose and fix the researcher's problem using the context gathered here.

## Start here

1. Read everything in **`context/`** — the facilitator's problem description (`context/problem.md`) and relevant links (`context/links.md`).
2. If **`context/SUMMARY.md`** exists, read it first — it is the overview produced by the `/init-request` command (problem, environment, scripts, links, open questions).
3. If it does not exist, run **`/init-request`** to build it.

## Directory structure

- **`scripts/`** — the researcher's scripts (copied in by the facilitator). This is the code under investigation.
- **`data/`** — input data used by the scripts. *(gitignored — may be large)*
- **`output/`** — output the scripts produce. *(gitignored)*
- **`context/`** — facilitator-authored context: `problem.md` (the issue), `links.md` (tickets/docs), `SUMMARY.md` (generated by `/init-request`), and **`logs/`** — researcher-uploaded build/job logs (*gitignored; the dir is kept via `.gitkeep`*). `/init-request` samples each log's head + tail (and triages build logs) rather than reading them whole.
- **`env_setup/`** — holds `renv.lock` (manifest of the reproduced R package versions, *tracked*) and `.renv-tools/` (the renv install used to generate it, *gitignored*). The R helper scripts themselves are **not** here — they are central scripts in the new_request repo's `bin/r/` (`r_env.sh` setup, `r_snapshot.sh` manifest, `r_install.sh` reproduce-an-install), run against this workspace.
- **`module_load.sh`** — **the activation script**; `source module_load.sh` to load the R module, set `R_LIBS_USER`, put the common `bin/` + the request's language tool(s) on `PATH`, and redirect caches/config into the workspace. *(gitignored)*
- **`R/<version>/`** — the reproduced R package library for that R module. *(gitignored — large)*

## Tools & assets available here

From the symlinked `.claude/` and (once you `source module_load.sh`) the `bin/<lang>` toolset on PATH:
- **`/init-request`** — build/refresh `context/SUMMARY.md`.
- **`triage-build-log` skill** — analyze a build/compile/install log and classify the failure (supports R, Python, C/C++, Fortran). Backed by `triage_build_log.sh`.
- **`r-install-debugger` agent** — reproduce a failing R package install and return a classified verdict (uses `r_install.sh`).

## Working conventions

- **Activate the environment before running anything R-related:** `source module_load.sh`. This also points `XDG_*`, `RENV_PATHS_ROOT`, and `R_ENVIRON_USER`/`R_PROFILE_USER`/`R_HISTFILE` into this workspace, so package caches/config/data stay here instead of the facilitator's home directory.
- **Check for a login node before any heavy build, and stop if you're on one.** The SCC scheduler sets `$NSLOTS` (and `$JOB_ID`) only inside a batch/interactive job; a shell without them is a **login node** (its hostname typically matches `scc[0-9]`/`scc-*`). Before running anything compile-heavy — `install.packages`, `R CMD INSTALL`, `make`/`cmake`, `configure`, a from-source build — verify you're in a job (e.g. `[ -n "$NSLOTS" ]`). If you're on a login node, **do not run the build**: warn the facilitator that heavy compilation on a login node is against SCC policy and will be slow/killed, and suggest requesting an interactive session first — e.g. `qrsh -P <project> -pe omp 4` (pick the core count to match the build). Proceed only once you're inside the job.
- **Parallelize builds by `$NSLOTS`, never a hardcoded core count.** Once in a job, use `$NSLOTS` for any build *you* launch — `make -j"$NSLOTS"`, `R CMD INSTALL` with `MAKEFLAGS="-j$NSLOTS"`, `install.packages(..., Ncpus=${NSLOTS:-1})`, etc. Caveat: parallel compiles raise peak memory, so if a build OOM-kills (see triage), cut the job count even when more cores are free. (The reproduction script `r_install.sh` deliberately stays at `Ncpus=1` to mirror the researcher's default — that's fidelity, not a core count to "fix.")
- The reproduced library is a **faithful copy** of the researcher's environment (same cluster, same R version/arch) — treat package versions as fixed evidence, not something to "fix" by upgrading, unless that is the diagnosis.
- `renv.lock` is the audit record of what was reproduced; consult it to reason about package versions.
- Don't write outside this workspace; don't modify the facilitator's home directory.

## Gotchas (read before running R / asserting dependencies)

- **Never pipe `source module_load.sh`.** Piping (e.g. `source module_load.sh | tail`) runs it in a subshell, so the environment does not persist and `Rscript`/`R` won't be found in later commands. Source it directly, then sanity-check with `which Rscript` before any heavy command. Each Bash call is a fresh shell, so re-`source` at the top of every R command (or bundle the R work into one Bash call).
- **Verify a package is actually a dependency before treating it as one.** Check the target's `Imports`/`Depends`/`LinkingTo` (e.g. `tools::package_dependencies()` or the package's `DESCRIPTION`) rather than assuming. (A companion package shipped alongside the target is *not* necessarily a dependency.)
- **Use the version-specific Bioconductor page** that matches the loaded module's Bioc release: `https://bioconductor.org/packages/<3.XX>/bioc/html/<pkg>.html`. The generic `/packages/release/` page describes the *current* package version, whose dependencies/`SystemRequirements` may differ from the one that installs on this R.
- **Stale `00LOCK-<pkg>` directories** in a library (an `R CMD INSTALL` lock left by an interrupted install) cause `failed to lock directory ... Try removing .../00LOCK-<pkg>` and `cannot install` errors. Check for and remove them early — in both the workspace library (`$R_LIBS_USER`) and, when relevant, the researcher's personal library.
